# 提示词版本索引

用途：回答"**哪一版改了什么、为什么改、验证没验证**"。每次运行都会把实际用到的提示词快照进
`runs/<run>/metadata/prompts/`，并在 `run.json` 里记录路径与 sha256；本索引补上人类可读的变更说明。

维护规则：

1. 改提示词 = 新建版本文件，**不修改历史版本**；
2. 新建版本时必须在下面补一行，四个要素写全：变更、为什么、验证、状态；
3. 同一时间每个角色只有一版标"当前"，必须与 `config/vlm-providers.json` 一致；
4. 还在试、没验证的思路先用草稿文件试，**验证通过后再冻结版本号**，避免版本号膨胀。

### v13 的稳定性实测（重要）

样本：化学 `2332243692174590286:7`（用户已确认伤正文）。像素剖面实测：正文末行墨迹在 y=1572–1591，
候选框 y1=0.905（约 1587）时**确实切掉正文末行约 5 像素**。

| 轮次 | body_changed | 说明 |
| --- | --- | --- |
| 提示词加强前 / 加强后共 6 轮 | true ×2、false ×4 | 同一页、同一事实，判定在翻转 |

结论：**5 像素级切口超出 VLM 的稳定分辨能力**，仅靠提示词无法保证 100% 命中。
兜底仍然成立——该页被 Java 门禁拦下，始终进人工审核、从不交付，正文红线没有被突破。
因此业务上建议：**凡 `manual_review` 一律保持原图**，把 `gate_audit=body_damaged` 当作辅助提示而非唯一依据。
